影像與像素

Image & Pixel

一句話定義

對電腦來說，一張影像就是一個排成格子的數字表，每一格叫做一個像素，數字代表那一點有多亮或是什麼顏色。

直覺理解

想像體育館裡的排字表演：每個人舉一張色板，從遠處看是一幅圖，走近看只是一格一格的色塊。每個人就是一個像素，色板的顏色就是那格的數值。

電腦沒有「遠處看」這件事，它永遠只拿得到那張數字表。電腦視覺要做的所有事情，不管是找邊緣還是認出貓，都是在這張數字表上做計算。

怎麼運作

灰階影像是一個二維矩陣，大小是「高 × 寬」。每格通常是 0 到 255 的整數：0 是黑、255 是白，中間是不同深淺的灰。這種 8 位元整數格式稱為 uint8。

彩色影像多了一個維度，叫做通道（channel）。最常見的是 RGB 三通道，等於疊了紅、綠、藍三張灰階圖，所以大小是「高 × 寬 × 3」。

灰階：H × W　　　彩色：H × W × 3　　　數值範圍：0 – 255（uint8）

丟進神經網路之前，通常會把數值除以 255 變成 0 到 1 的小數，這一步叫做正規化，能讓訓練更穩定。

# 用 NumPy 做一張 5×5 的灰階小圖：黑底白色十字
import numpy as np

img = np.zeros((5, 5), dtype=np.uint8)   # 全部是 0（黑）
img[2, :] = 255                          # 第 3 列塗白
img[:, 2] = 255                          # 第 3 行塗白

print(img.shape)   # (5, 5)
print(img[2, 2])   # 255，正中央是白色

# 彩色影像：多一個通道維度
rgb = np.zeros((5, 5, 3), dtype=np.uint8)
rgb[..., 0] = img                        # 只放進紅色通道 → 紅色十字
print(rgb.shape)   # (5, 5, 3)

x = img.astype(np.float32) / 255.0       # 正規化到 0–1
print(x.max())     # 1.0

算算看檔案有多大

一張 1920 × 1080 的彩色照片，有 1920 × 1080 × 3 ≈ 622 萬個數字，每個數字佔 1 位元組，未壓縮就是大約 6 MB。這也是為什麼神經網路通常會先把影像縮小到 224 × 224 之類的尺寸再處理。

常見誤解

  • 像素是一個小正方形。像素其實只是一個取樣點的數值，顯示器把它畫成小方塊只是呈現方式。所以放大影像時，電腦要「猜」中間的值（內插），而不是把方塊拉大。
  • 所有函式庫讀進來的彩色圖都是 RGB 順序。OpenCV 的 cv2.imread 讀進來是 BGR 順序。直接拿去用 Matplotlib 顯示，紅色和藍色會對調，這是新手最常踩的坑。
  • 影像的大小寫成「寬 × 高」，所以陣列也是 (W, H)。NumPy 陣列是 (列, 行)，也就是 (H, W)。img[y, x] 先放縱座標，跟數學上的 (x, y) 順序相反。
